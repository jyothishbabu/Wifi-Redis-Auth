One Jamf configuration profile gives every Mac its own certificate and the {{ ssid }} network, like Intune does for Windows. Each Mac creates its own key (it never leaves the Mac), and Jamf renews certificates automatically.

Create the profile in Jamf Pro (once)

Jamf Pro → Computers → Configuration Profiles → New. General: name Wi-Fi {{ ssid }}, Level Computer Level, Distribution Install Automatically. Add three payloads:

PayloadSettings
CertificateName Redis Root CA · Select Certificate Option Upload → Redis-Root-CA.cer
SCEP URL {{ sc.url }} · Name Redis
Subject CN=$SERIALNUMBER · Subject Alternative Name: DNS Name $SERIALNUMBER
Challenge Type Static · Challenge: the challenge above (both fields)
Key Size 2048 · tick Use as digital signature and Use for key encipherment
Fingerprint {{ sc.fingerprint }} · leave Allow export from keychain unticked
Network Network Interface Wi-Fi · SSID {{ ssid }} · tick Auto Join · Security Type WPA2 Enterprise
Protocols: accepted EAP type TLS · Identity Certificate: the SCEP payload
Trust: tick Redis Root CA · Trusted Server Certificate Names {{ s.server_name }}

Scope: a smart group of the Macs that should use {{ ssid }} (start with 2–3 pilot Macs). Each Mac must be on an office network (wired, guest Wi-Fi or a VPN leaving from an office IP) when the profile installs, because the panel only answers office IPs. If a Mac was away, use Redistribute on the profile once it is back.

Check: the Mac shows the profile in System Settings → Device Management, connects to {{ ssid }} by itself, and appears on the Logins page as ACCEPT (named after its serial number, or its Jamf name once section 2 is connected).
